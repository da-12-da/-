

# 项目名称

> **就这么定**：一款旅行决策工具。当你和朋友在一起玩、不知道该听谁的、该去哪、或者无聊没想法的时候，把你们的想法告诉**它**，让**它**帮你决定。最重要的是，不只是做决策，还可以体验选择的乐趣。

---

## 1.项目背景与痛点

### 1.1 背景

和朋友一起旅游时，大家经常需要临时决定

“吃什么呢？”，“去哪儿吃呢？”，“接下来玩什么好呢？”，“太无聊了，不知道去哪里。”

每个人都有不同的想法，很难快速达成一致。

本产品聚焦**多人旅行决策场景**，通过"**收集想法 → 转盘选择 → 附近推荐 → 目的地导航**"的完整流程，帮同行小伙伴快速结束选择纠结。不再反复拉扯、互相妥协，把选择难题变成一场轻松愉快的社交小游戏。

### 1.2 痛点

- **意见难统一**：多人出行时口味、兴趣各不相同，"我都行" 看似妥协实则把决策压力甩给他人；少数服从多数又容易让部分人带着情绪妥协，一场讨论耗时很久仍定不下来。
- **陌生地点不好选**：旅行途中不了解周边商家、景点、距离、人均、排队情况，要在多个平台反复对比，越看越纠结。
- **选完品类还得选店**：好不容易定了 "吃火锅" 这个品类，紧接着又陷入 "去哪家火锅" 的第二轮选择，品类决策和店铺决策之间没有衔接，相当于纠结了两次。
- **操作不够连贯**：线上\线下讨论想法、用小程序转盘随机选择、打开地图搜店、再切到导航 APP，整个决策流程横跨四五个工具，操作繁琐且容易被打断。

## 2.需求详情

| 编号 | 优先级 | 需求点名称 | 需求点描述 |
| :--- | :--- | :--- | :--- |
| R1 | P0 | **添加大家的想法** | 支持添加、编辑和删除选项，例如"火锅、烧烤、自助、小炒"。首期由一人在同一台手机上汇总大家的意见。 |
| R2 | P2 | **转盘随机选择** | 将选项展示为转盘，每个选项被选中的概率相同。点击后转动并突出显示结果，支持重新转动。 |
| R3 | P1 | **推荐附近同类商家** | 获得位置授权后，根据抽中的品类，默认搜索周边 3 公里内的商家，推荐口碑靠前的 3 家。<br>展示店名、距离、地址、评分，以及数据源实际提供的好评率和评价数量。标明推荐依据，不将评分换算为好评率；不足 3 家时展示实际数量，并支持扩大范围。 |
| R4 | P1 | **确定商家并出发** | 用户从推荐商家中选择一家，确认本次目的地，并打开地图导航。拒绝定位时，支持手动输入目的地或所在区域。 |

## 3.验收标准及MVP规划

### 3.1 验收标准

- **R1添加大家的想法**：
  - 支持新增、编辑和删除餐饮选项，操作后列表与转盘同步更新
  - 按当前原型支持 2–8 个选项，不足 2 个时不能开始转盘，达到 8 个时不能继续添加，并给出提示
  - 空白或重复选项不能提交，错误提示明确，已有内容不丢失
  - 修改选项后，旧的抽选结果和商家选择失效，需重新转动
- **R2转盘随机选择**：
  - 转盘展示全部有效选项，扇区等分；随机选择逻辑保证每个选项概率相同，不要求少量抽选次数完全平均
  - 点击中心 GO 后开始转动，转动期间不能重复触发或修改选项
  - 停止后，指针对应的选项与实际抽选结果一致，并自动进入独立结果页
  - 结果页展示抽中的品类及“查看附近的店”按钮，按钮品类与结果一致
  - 支持返回转盘再次点击 GO，重新抽选并更新结果
  - 手机及车内横屏下，转盘完整显示，旋转过程中不出现横向或纵向滚动条
- **R3推荐附近同类商家**：
  - 取得位置后，以当前查找位置为中心，默认搜索 3 公里内与抽中品类匹配的商家
  - 按明确的口碑排序规则，从接口返回的有效候选中展示最多 3 家，标明数据来源及推荐依据
  - 店名、地址、评分等信息与接口返回一致；距离明确计算口径，不将直线距离标为导航路程
  - 好评率、评价数量仅在数据源提供时展示，缺失时标注“暂无数据”或隐藏，不编造，也不将评分换算成好评率
  - 不足 3 家时展示实际数量；扩大搜索范围后重新查询，更新范围标识和推荐结果
  - 无匹配商家、请求失败或数据未接入时，显示对应提示，不以示例数据替代真实推荐
  - 更换品类、位置或范围后，清除旧商家选择；较早请求的返回结果不得覆盖最新查询
- **R4确定商家并出发**：
  - 支持选择一家推荐商家，选中状态清晰，确认后进入目的地页面
  - 目的地页面的店名、地址与所选商家一致，不发生错店或分店混淆
  - 点击导航后打开所选地图，目标位置与商家坐标一致，跨地图使用时正确处理坐标系
  - 地图无法打开时给予明确提示或可用替代入口，不出现无反馈点击
  - 拒绝定位或定位失败后，仍可手动选择城市、区域或目的地，确认位置后可继续查询附近商家
  - 返回重新选店后，目的地信息和导航目标同步更新

### 3.2 MVP 规划

#### MVP 1.0

- **目标**：聚焦旅行中的多人聚餐决策，由一人在同一台手机上汇总大家的想法，跑通“录入餐饮选项 → 转盘选品类 → 独立结果展示 → 推荐附近商家 → 选店导航”的完整流程，验证产品能否帮助同行伙伴更快确定用餐去处
- **包含功能**：
  - 餐饮选项管理： 支持添加、编辑、删除选项，设置数量限制，校验空白和重复内容
  - 随机转盘： 各选项被抽中的概率相同，点击中心 GO 开始转动，支持返回后重新抽选
  - 独立结果页： 展示抽中的餐饮品类，并提供“查看附近的店”入口
  - 附近商家推荐： 接入一个真实商家数据源，默认查询周边 3 公里，按明确规则推荐最多 3 家同类商家，展示可获取的评分、距离和地址
  - 选店与导航： 用户选择商家、确认目的地后，打开地图导航
  - 基础异常处理： 支持定位失败后手动选择区域、商家不足时扩大范围，以及无结果、接口失败时的提示
  - 界面适配： 支持手机竖屏和供同行乘客使用的车内横屏布局
- **暂不包含**：多人在线同步、投票、账号体系、预订支付、个性化推荐，以及景点、住宿等其他旅行决策
- **上线前提**：
  - 核心流程通过验收，商家查询和导航经真实环境验证
  - 明确数据来源及推荐依据，缺失评分或好评率时不编造
  - 未接入真实数据时，仅作为明确标注的演示版本，不视为完整 MVP 上线
- **验证指标**：
  - 流程完成率： 开始录入选项的用户中，最终确认商家的比例
  - 决策耗时： 从开始录入选项到确认商家的时间
  - 推荐承接率： 查看转盘结果后，继续查看附近商家的比例
  - 导航转化率： 确认商家后，点击导航的比例
  - 用户反馈： 是否减少反复讨论，转盘结果是否容易被同行伙伴接受
